# TWORLD

Личное PWA для трекинга тренировок, вредных привычек и дневника.
Django + DRF + PostgreSQL на бэкенде, React + Vite + TypeScript на фронте.

Приложение сделано вокруг одного принципа: **если ввод занимает больше
3 секунд или больше 2 тапов — он переделан**. Предыдущая версия провалилась
не из-за нехватки функций, а из-за того, что данные было неудобно вносить,
и человек начинал врать себе или бросал.

## Быстрый старт

### Вариант 1 — Docker (ничего не надо ставить)

```bash
cp .env.example .env
docker compose up --build
```

- фронтенд: http://localhost:5173
- API и документация: http://localhost:8000/api/docs/
- админка: http://localhost:8000/admin/

Демо-данные (90 дней истории) подгружаются отдельной командой:

```bash
docker compose exec backend python manage.py seed_demo
# вход: @demo_user / demo12345
```

### Вариант 2 — локально

Нужны Python 3.11+, Node 20+, PostgreSQL 14+.

```bash
# --- база ---
createuser tworld --createdb --pwprompt      # пароль: tworld
createdb -O tworld tworld

# --- бэкенд ---
python -m venv .venv && source .venv/bin/activate
pip install -r backend/requirements.txt
cp .env.example .env
python backend/manage.py migrate
python backend/manage.py seed_catalog        # справочники и библиотека упражнений
python backend/manage.py seed_demo           # демо-пользователь на 90 дней
python backend/manage.py runserver

# --- фронтенд (во втором терминале) ---
cd frontend
npm install
npm run dev
```

Открыть http://localhost:5173, войти как `demo_user` / `demo12345`.

В разработке фронтенд ходит по относительному `/api`, а Vite проксирует
запросы на бэкенд — CORS настраивать не нужно. Если бэкенд поднят
на другом порту:

```bash
VITE_DEV_API_PROXY=http://127.0.0.1:8001 npm run dev
```

### Проверка

```bash
cd backend && python -m pytest             # 54 теста: изоляция данных и доменные правила
cd frontend && npm run typecheck && npm run build
cd frontend && npm run e2e                 # сквозной прогон в Chromium под iPhone 14 Pro
cd frontend && npm run e2e:workout         # запись подхода, таймер отдыха, шаг по сетке зала
cd frontend && npm run e2e:screens         # все девять вкладок «Прогресса»
```

## Оформление — один файл

`frontend/src/styles/tokens.css` содержит **все** визуальные параметры:
цвета, шрифты, размеры, отступы, радиусы, тени, длительности анимаций,
тап-зоны и безопасные отступы iPhone. Ни один компонент не содержит
хардкода — только `var(--…)`.

Сейчас там нейтральные заглушки: серая шкала и системный шрифт. Чтобы
подключить настоящий стиль, достаточно заменить значения в этом файле —
разметку трогать не нужно. Тёмная тема переопределяет те же токены.

Семантические токены (`--color-warn`, `--color-ok`) тоже серые: предупреждение
о резком скачке веса должно быть заметным, но не выглядеть аварией.
Приложение не ругает пользователя цветом.

## Решения, которые стоит знать до правок кода

**Длительности хранятся только в целых секундах.** В схеме нет ни одного
`TimeField` или `DurationField` для длительности упражнения. `85` — это
85 секунд, а не «час двадцать пять». Формат «1:15:37» невозможно ввести
физически: раньше именно он превращал 1 мин 15 сек в 1 час 15 минут
и ломал все агрегаты.

**Вес односторонних упражнений умножается на два.** У `SetLog` есть поле
`weight_is_per_side` — снимок флага упражнения на момент записи. Если
поменять флаг у упражнения задним числом, история не поедет.

**Сетка весов принадлежит паре «зал × упражнение».** `GymExerciseProfile.weight_steps`
хранит фактические значения тренажёра (`[36.2, 40.8, 45.3, 49.8, 54.4, 58.9]`),
кнопки +/− ходят по этому массиву. Один и тот же тренажёр в разных залах
даёт разные цифры.

**День выполнен, если закрыт блок `required`.** Статуса «тренировка провалена»
в схеме нет вообще. `main` и `optional` на зачёт не влияют.

**Пропуск по внешней причине не портит дисциплину.** Решает флаг
`FailReason.counts_against_discipline` на справочнике причин, а не код.
Пользователь может переопределить его в настройках.

**Срыв привычки не стирает историю.** Все три числа — «дней с решения»,
«текущая серия», «всего чистых дней» — вычисляются из событий, а не хранятся
счётчиками. Поэтому отметка задним числом пересчитывает их честно,
а «дней с решения» не обнуляется никогда.

**Основная цифра веса — тренд, а не сырое значение.** Скользящее среднее
за 7 дней пересчитывается при каждой записи. Разница между утренним
и вечерним весом доходит до 3 кг, и сырые цифры демотивируют зря.

**Калории выключены по умолчанию** (`UserSettings.track_calories = False`).
Пока выключено, в интерфейсе нет ни одного поля калорий — только белок.

## Изоляция данных

Три слоя, а не один:

1. `OwnedModel` — обязательный `user` с каскадным удалением у всех
   пользовательских таблиц.
2. `OwnedModelViewSet.get_queryset()` всегда сужает выборку до `request.user`;
   владелец при создании берётся из запроса, поле `user` в теле игнорируется.
3. Тесты `backend/tests/test_isolation.py` проходят по реестру всех роутов
   и падают, если появится вьюсет без обязательной фильтрации. Плюс проверка
   «юзер Б получает 404 на объекты юзера А» по каждой модели.

Удаление аккаунта (`POST /api/accounts/delete/` с подтверждением ником)
удаляет все данные каскадом.

## Деплой

`docker-compose.yml` описывает конфигурацию для разработки. Для продакшена:

1. `DJANGO_DEBUG=False`, свой `DJANGO_SECRET_KEY`, реальные `ALLOWED_HOSTS`.
2. `python manage.py collectstatic`, статику и `media/` раздаёт nginx.
3. Бэкенд под gunicorn: `gunicorn config.wsgi --bind 0.0.0.0:8000 --workers 3`.
4. Фронтенд: `npm run build`, содержимое `frontend/dist/` раздаёт nginx
   с фолбэком на `index.html`.
5. **HTTPS обязателен** — без него Service Worker не зарегистрируется,
   а значит не будет ни оффлайна, ни установки на домашний экран.
6. PDF-отчёты требуют системных библиотек Pango и Cairo (в `backend/Dockerfile`
   они уже стоят). Без них отчёт отдаётся печатаемым HTML — «Печать →
   Сохранить как PDF» даёт тот же A4.

## Apple Health

PWA не имеет прямого доступа к HealthKit — это ограничение iOS, а не проекта.
Поддерживаются два пути без нативного приложения, оба через
`POST /api/health/import/` (формат — в [docs/ai-exchange-format.md](docs/ai-exchange-format.md)):

1. **Apple Shortcuts → вебхук.** Автоматизация «каждое утро отправить сон,
   шаги и пульс покоя». Настраивается за пять минут, работает без App Store.
2. **Выгрузка `export.zip`** из приложения «Здоровье» — разовый импорт истории.

Повторная отправка тех же данных дублей не создаёт, а ручной ввод импорт
не перезаписывает: ручное значение всегда главнее.

## Интеграция с нейросетями

```bash
# весь контекст готовым markdown
curl -H "Authorization: Token twk_..." \
  "http://localhost:8000/api/context/?format=markdown"

# импорт плана обратно
curl -X POST -H "Authorization: Token twk_..." -H "Content-Type: application/json" \
  -d '{"text": "# Верх тела\n\n## Обязательный\n| Упражнение | Подходы | Повторы | Вес |\n|---|---|---|---|\n| Жим штанги лёжа | 4 | 6-8 | 62.5 |"}' \
  http://localhost:8000/api/plans/import/
```

Токены создаются в приложении: Профиль → Интеграции. Токен со скоупом
`read` физически не может изменить данные — это проверяется на сервере.

MCP-сервер (девять инструментов, включая `log_workout` и `create_plan`):

```bash
pip install -r backend/mcp_server/requirements.txt
TWORLD_API_URL=http://localhost:8000/api TWORLD_TOKEN=twk_... \
  python -m mcp_server.server
```

## Демо-данные

`python manage.py seed_demo --reset` создаёт пользователя `@demo_user`
с 90 днями истории. В данные намеренно заложены случаи, без которых
половину логики не проверить глазами:

- резкий скачок веса на жиме гантелей — и травма плеча следом;
- второй эпизод той же травмы внутри 60 дней (сработает предупреждение о рецидиве);
- трёхнедельный застой в тяге верхнего блока;
- неделя недосыпа с провалом самочувствия в зале;
- упражнение, пропущенное шесть раз подряд (сработает подсказка о порядке);
- срывы привычки с сохранённой историей;
- девять недель без разгрузки (сработает предложение деload).
